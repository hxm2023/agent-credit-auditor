## 1. 背景速成（给不懂这个领域的人讲）

### 1.1 大模型是怎么"练"出来的

大模型不是写代码写出来的，是"练"出来的。一种主流练法叫 **GRPO**
（Group Relative Policy Optimization），可以用驾校教练类比：

1. 让模型自己开一遍车（生成一段回答 / 执行一个任务）；
2. 给这次表现打分（任务成功 = 高分，失败 = 低分）；
3. 调整模型，让"得高分的做法"以后更容易出现。

### 1.2 什么是 credit assignment（信用分配）

一段 200 字的回答，模型其实是逐词做了 200 次"下一步选哪个词"的小决定。
**最后只给了一个总分**——问题来了：这 200 个小决定里，哪些是好决定？
该把功劳记在谁头上？"把总成绩分解到每一步决策上"就是 credit assignment。

**具体例子**：训练一个"订票助手"，动作序列是
`① 查余票 → ② 选航班 → ③ 填乘客信息 → ④ 支付 → ⑤ 出票`。
最后订票成功，但功劳在②（选对航班）还是④（支付顺利）？如果④之前被系统
自动纠正了③的错误，模型可能学到"填错身份证也没关系"这种坏习惯。

### 1.3 这个项目真正解决的问题

这个领域有几十种 credit assignment 方法，每篇都声称更好。但我自己踩过一个
事故：**拿到 36.5%→63.5% 的成功曲线，最后发现生成数据的 rollout 一直用的是
初始化时的静态模型**——曲线测的是一个从未进化的旧模型（训练器在更新权重，
采样器没有跟着换）。用生活例子说：**你测试了三个月的健身方案，最后体检的
是三个月前的你自己。**

这个事故暴露了一个更普遍的问题：**这个领域缺的不是新方法，是"验证方法是
真的"的标准**。所以我没有继续调参，而是建了这台"质检台"。

> 从未进化的旧模型。我没有继续调模型，而是建了这个审计工具：逼每个 credit
> 估计方法回答四个问题——在估什么、有没有偏差、同预算下值不值、机制是不是

### 2.2 3 分钟版（主动讲项目时）

**钩子（30s）**：36.5%→63.5% 的曲线是假的——rollout policy 静态不更新，
测的是旧模型。我停手了，因为我意识到：先要能分辨真假，再谈改进。

**装置（90s）**：任何 credit assignment 方法必须过四道门——
1. **Estimand**：说不清在估什么 → 我在精确小世界里把目标算到数学精确。
   *抓到*：把局部对比传播到共享前缀的方法，传播部分**期望精确为 0**——
   它在更新一个数学上不存在的方向。
2. **Bias**：两个独立 oracle（路径枚举 + Bellman 动态规划，独立进程、
   零共享代码、import 隔离）验证到 **mismatch == 0**（分数精确算术，
   不是容差）。
3. **Cost**：所有方法记同一本成本账，同预算比 MSE。
   *抓到*：一个校准误差 1e-16 的方法，固定预算 MSE 差 dense **26.5 倍**。
4. **Mechanism**：把校准出的参数摊开看。
   *抓到*：一个"自适应可变宽度"方法指标赢 5 倍，但宽度全塌缩成
   **[2,2,2,2]**——和固定对照完全一样。我主动关掉了它的 adaptive claim。

**桥接（30s）**：精确领域再漂亮也要证明能预测真实。我造了可控的 tool-agent
世界，exact 层的预测公式（方差×成本÷预算 + 偏差²）复现真实采样 MSE 的
比率落在 **0.87-1.07**（预测误差 <13%）。

**闭环（30s）**：在共享 8×A800 上跑完 **18 次** Guard 监督的真实 GRPO 训练
（2 任务 × 3 估计器 × 3 随机种子，Qwen3-4B + LoRA）。dense/local 每轮真实
更新（梯度范数 ~4.9）；paired 分支的可靠性门 **9/9 全部弃权**（选择零更新
而不是瞎更新）；第二个任务全部零奖励（诚实负结果）。全部轨迹过离线审计：
768 条/run，零违规。

## 3. 技术解剖（七层，问哪层答哪层）

### 3.1 第一层：精确世界（Exact World）

**做什么**：造一批"能精确枚举的小型序列决策问题"（MDP），4-6 步决策，
每步两个动作。所有可能的路径数量 = 2^H（H≤6 时最多 64 条），每条路径的
概率是若干概率的乘积。

**为什么能"精确"**：
- 路径数量有限 → 可以一条条全列出来；
- 所有概率/奖励用**分数（Fraction）**表示（如 3/8 而不是 0.375）→
  加法和乘法没有浮点舍入误差；
- 于是在这个世界里，"偏差"可以算到**字面意义上的 0**（不是"小于 1e-15"）。

**证据**：12 个冻结问题上，主实现与两个 oracle 的对齐结果
`mismatch == 0`（`all_exact: true`）。

**面试官可能追问**：
> "分数算术不会很慢吗？" —— 在这些小世界上不慢（H≤6，路径 ≤64 条）；
> 大规模的那个普查（1000 万家族）也用了分数精确算术，在 48 核上 88 秒。

### 3.2 第二层：独立 oracle（防共谋的基准）

**两个 oracle，两种完全不同的算法**：
1. **枚举法**：把所有路径列出来，概率 × 奖励加总（笨但直观）；
2. **Bellman DP**：从终点倒推期望值（聪明但实现复杂）。

**独立性怎么保证（这是关键设计）**：
- oracle 是**独立子进程**，只用标准库（stdlib-only）；
- **AST 级 import 隔离测试**：静态分析 oracle 代码的 import 图，
  确保它不引用被测估计器的任何模块；
- **monkeypatch 破坏测试**：故意破坏主实现的依赖，验证 oracle 不受影响；
- 任一 oracle 与主实现不一致 → 该实验判 **INVALID**（E002）。

**面试要点**："独立"不是口号，是四条可执行的检查。

### 3.3 第三层：估计器与数学（面试官要考你的地方）

**符号**：步骤 t 的动作 a_t（0/1），行为策略给该动作的概率 π_t。
定义**中心化指示特征**（score）：
```
s_t = a_t − π_t
```
在 logit 参数化下它正好是 ∇log π(a_t) 的等价形式。

**全梯度目标**（要估计的量）：
```
g* = E[ R(τ) · Σ_t s_t ]
```
其中 R(τ) 是整条轨迹的回报。

**四个被测估计器**：

| 名字 | 公式 | 性质 |
|---|---|---|
| **dense** | `ĝ = R(τ)·Σ_t s_t` | 无偏（bias ~1e-16），但方差大 |
| **local sibling** | `ĝ_t = (R(τ) − R(τ^{t→a'}))·s_t`，只更新坐标 t | 对"局部效应"无偏，对全梯度**有偏** |
| **propagated sibling** | 同上对比，但更新**所有坐标** | **期望为 0**（在 t'<t 上，对比量条件均值为零）→ T003 拒绝 |
| **paired replay** | 每个坐标用自己的对比，**后缀共享**（耦合） | 在独立坐标世界里对全梯度无偏 |
| **PC-RSG 类** | `ĝ = R Σs + (contrast_t − R·s_t)/q_t` | 期望正确（校准 1e-16），方差被 1/q 放大 |

**HH vs HT（抽样加权）**：
- **Hansen-Hurwitz**：有放回抽样时用选择概率倒数 1/q（每个"入选的"补上
  它代表的总体份额）；
- **Horvitz-Thompson**：无放回抽样时用包含概率 — 一个单元在 n 次抽样中
  至少入选一次的概率。
- **混用两者 = S003**（一个经典错误：在无放回场景使用 1/q 会系统性高估）。

**固定预算 MSE 的分解**（Stage 2 的预测公式来源）：
```
MSE ≈ var_cycle · cost / B + bias²
```
含义：每个"估计周期"有固有方差 var，每次周期消耗 cost 个 transition，
总预算 B → 能跑 B/cost 个周期 → 平均值的方差 = var·cost/B；
再加上偏差的平方。**这个公式是 Stage 2 的预注册预测。**

**K-sample prefix floor（为什么"加宽采样"有天花板）**：
对共享前缀的估计器，方差可以分解为
```
Var(ĝ) = E[Var(ĝ | prefix)]  +  Var(E[ĝ | prefix])
```
第二项只取决于**前缀的分布**，不管你在后缀上采多少样本都消不掉。
所以"把采样宽度 K 加大"的方法在固定预算下有一个够不到的下界。

**HH 的 1/q 放大**（V001 失败的机制）：
```
Var(ĝ_HH) = Var(R·s)/q + g*² · (1/q − 1)
```
q 越小（越少采到那个决策），第一项的 1/q 越大，第二项的 (1/q−1) 也越大。
所以"低概率决策上做残差校正"会把噪声放大很多倍。

### 3.5 第五层：三个主实验（每个都有完整故事）

**M0 — 目标审计**（12 个冻结问题，5 个 designed cases）
- 问题：不同估计器声称估计的目标是否一致？
- 做法：在同一批精确问题上跑 dense / sibling / propagated / BPO-like /
  paired-replay，与精确目标对比。
- 结果：dense 与 uniform-HH **无偏**（bias ~1e-16）；local sibling 对
  局部效应无偏但**对全梯度有偏**；**propagated sibling 与 BPO-like 被拒**
  （T003）；paired-replay 在预注册的 matched-cost 正例上赢 dense **57 倍**
  （MSE ratio 0.017），去掉配对耦合的对照组**输 7 倍**——赢的是机制。

**V001 — 效用失败**
- 问题："校准准确"能不能推出"有限预算下好用"？
- 做法：一个 PC-RSG 式残差校正估计器，先验证它的期望（校准），再比
  固定预算 MSE。
- 结果：校准误差 ~1e-16（20 个校准问题，最大 1.5e-16），但固定预算 MSE
  中位数是 dense 的 **26.5 倍**（bootstrap CI [16.8, 42.9]），比 HH 也差
  **3.06 倍**（CI [2.68, 3.30]）。原因：1/q 方差放大 + 分支成本。

**D002 — 双裁决（旗舰）**
- 问题：一个"自适应变宽"的方法，指标赢了，机制真的在工作吗？
- 做法：先在校准集上让方法自己选参数（映射 + 宽度），冻结选择，再在
  48 个 held-out 问题上测试。
- 结果：**指标 PASS**——median ratio **0.205**（CI [0.177, 0.229] vs
  dense envelope）；**机制 FAIL**——4 个问题上选出的宽度全部是 **[2,2,2,2]**，
  等于全局固定对照（MECH001），且落在候选宽度零分布的 0 分位（p≤0.05）。
- 处置：我主动把 adaptive claim 关掉，只保留"固定映射效率"的窄结论。

### 3.6 第六层：深化与自审计

- **CTRI 普查**：在冻结的 continuation 家族上做符号/秩稳定性普查。
  5k → 100k → 10M 三档规模，reversal 率 2.88% → 3.244% → **3.2744%
  ±0.006pp** 收敛稳定。10M 那次在服务器 48 核上 **88 秒**跑完，**0 GPU**。
  意义：量化"小样本结论翻转"的普遍程度（约每 30 个家族一个）。
- **机制理论**：把三个关键结论写成闭式推导——paired-replay 的方差公式、
  K-sample prefix floor、HH 的 1/q 放大——每个都用数值验证 ==0 diff。
  意义：不只是"测出来"，还知道"为什么是结构性的"。
- **自审计（审计器的审计）**：把 13 类故障注入自己的流水线，验证每类都被
  预期 code 抓到；开发中真的抓出我 3 个对照组构造 bug。
  诚实边界：模板与预期 code 是同源构造的，所以只声称"预定义故障的回归
  检测"，不声称对未知故障的通用 TPR/FPR。

（token 序列 + 动作掩码 + 旧日志概率 + 奖励 + 策略版本），离线检查六类故障：
mask 错位（T005）、日志概率长度/数值异常（S002）、token 重切（T005）、
策略版本缺失或混用（T004）、估计器掩码与优化器实际消费掩码不一致（T005）、
记录不可解析（P001）。演示中六类故障全部检出，干净基线保持干净。

**Stage 2 — 证据桥**：可控 tool-agent 世界（观察依赖：上一步的调用结果会
改变下一步的决策概率），两层验证：
- exact 层：每个估计器的**周期分布**精确枚举（路径 × sibling 抽取）；
- sampled 层：同样的估计器只消费轨迹记录，在**匹配预算**下测固定预算 MSE；
- 独立 MC 参考：自己的随机流、自己的代码路径（不 import 估计器）。
结果：预测比率 **0.87-1.07**；自校验（周期 MC == 精确均值，6σ 门）全部通过；
transfer finding：paired-replay 的无偏性在观察依赖世界里**不成立**——
配对对比漏掉了"决策 → 未来观察 → 未来决策"的**间接效应**。

**Stage 3 — 真实闭环**：18 次 Guard 监督的真实 GRPO（Qwen3-4B + LoRA，
32 prompts × 8 gens × 3 epochs/次）。每次训练：
身份校验 → 打分事件 → 更新前审批 → 材料化 → 受控更新 → 提交 adapter →
canary。结果：
- dense/local：每 epoch 真实更新，梯度范数 4.89 / 4.86；
- paired：可靠性门 **9/9 弃权**（NO_RELIABLE_CREDIT / DEGENERATE_GROUP），
  即零 credit、零更新；
- tau2 任务：基础模型产出无效工具调用率 100%，奖励全零，所有估计器零信号；
- 最终评估：cts_order 全部 mean_u 0.875（未变），tau2 全部 0.0；
- 轨迹审计：18 run × 768 条记录，**零违规**。

## 5. 30 个高频拷问 + 应答（含追问链）

> 格式：**Q** 面试官问 → **A** 直接回答 → **展开** 你可以补充的细节 →
> **追问** 面试官可能接着问什么。

### A 组：定位与意义（Q1-Q5）

**Q1. 一句话说这个项目是干什么的？**
**A**：给 agent RL 的 credit assignment 方法做审计的工具。不是新算法，是
一套"逼每个方法回答四个问题"的验证系统：估什么、偏不偏、值不值、机制真不真。
**展开**：它有两个组成部分——一套精确可枚举的基准世界（含独立 oracle），
和一套 reason-coded 的门禁。任何方法接入后，产出的是"哪道门过了、哪道门
失败、为什么"的结构化裁决。
**追问**："四道门是谁定的？" → 来自我自己踩的坑和领域里常见的四类混淆
（target 说不清、预算不公平、机制没发生、split 污染），在 design doc 里
lock 死，并且每道门都有对应的 reason code 和回归 fixture。

**Q2. 不出新算法、没有 SOTA 数字，价值在哪？**
**A**：这个生态里最大的问题不是方法少，而是"漂亮曲线"和"真实效果"经常
脱节。我自己就踩过：静态 rollout 的假曲线。我做的是**把这种判断标准化、
可复现化**——判别力本身就是产出。
**展开**：举个量化例子：V001 那一类方法，校准误差 1e-16（看起来无懈可击），
但固定预算 MSE 差 26.5 倍。如果没有这套审计，这个失败会被"校准很准"掩盖。
**追问**："那你的工具自己准吗？" → 自审计：13 类故障注入全部被抓，
对照组零误报，而且开发中真抓出我 3 个 bug。

**Q3. 你自己方法被这个工具否决过吗？**
**A**：有，而且这是最有说服力的部分。D002 那个"自适应变宽"是我自己的路线，
被自己的机制门否决后我主动关掉了 adaptive claim，只保留"固定映射效率"的
窄结论（宽度塌缩成 [2,2,2,2] = 全局对照，MECH001）。
**追问**："主动关掉不心疼吗？" → 心疼，但如果我保留它，将来被别人复现出
塌缩会更难看。审计工具的第一个用户必须是自己的良心。

**Q4. 这个项目和另一个项目（GRPO-Guard）什么关系？**
**A**：一条信任链的两半。Guard 管**在线**：轨迹生成时的模型身份、token/mask、
日志概率、权重同步必须是真的。Auditor 管**离线**：即使轨迹是真的，也要审计
"估计器声称的东西"是不是真的。
**展开**：两个仓库互相引用——Guard 签发的 envelope 流进 Auditor 的
`CreditAuditBundle` 校验（hash-only 引用、fail-closed 钉在 Guard 的 schema
版本 `grpo-guard-envelope-1.0`、不写回）；Stage 3 的 18 次训练就是 Guard
监督训练、Auditor 审计轨迹。**跨项目一致性**体现在同一套故障分类：Guard
在线抓 static_rollout/mask_shift，Auditor 离线用 T004/S002 抓同一类问题。
**追问**："那你们的 schema 谁定？" → Guard 定它自己的 envelope schema，
我不 fork、不修改，只按它的序列化格式读取并做版本 pin；我的轨迹记录格式
（`aca-trajectory-record-1.0`）是我自己的，等 Guard 发布轨迹 schema 后再做
适配层。

**Q5. 这个项目有哪些明确的边界？**
**A**：三条。① 不证明真实 LLM 下游收益——Stage 3 的最终评估指标没变
（3 步小 LoRA 本来就是机制级实验）；② 精确世界不外推到真实任务分布；
③ 历史数字（144/202、0.694、ρ=0.735）只当事故背景，从不作为复现结果。
**展开**：我把这些写进了 claims 政策：哪些话允许说（finite-MDP 无偏性、
matched-budget 比较、机制失败演示）、哪些禁止（"提出新算法"、"真实 LLM
收益"）。**主动说边界比被问出来好**——面试官问"你这能推到 GPT-4 吗"时，
我可以说"不能，而且我在文档里写明了不能"。

### B 组：方法论深挖（Q6-Q15）

**Q6. 精确小世界不是玩具吗？跟真实 LLM 有什么关系？**
**A**：分三层。第一层，小世界的价值是**可控**——真实场景没法算真值，也就
没法测偏差；小世界能精确算。第二层，我做了**证据桥**：在可控工具智能体
世界里，验证"精确层的预测公式（方差×成本÷预算 + 偏差²）能预测采样层的
MSE"，比率 0.87-1.07。第三层，**真实闭环**：18 次真实 GRPO 训练。
**展开**：关键在第二层的设计——两个层用**同一批估计器定义**（不是重写），
采样层只消费轨迹记录（不接触环境），这样"同一套判断"是在同一对象上验证的。
**追问**："预测比率 0.87-1.07 是怎么算的？" → 对每个"估计器×任务"组合：
精确层算出预测 MSE（var·cost/B + bias²），采样层在相同预算下跑 40 个
重复批次测 MSE，比值 = 实测/预测，全部落在 0.87-1.07。

**Q7. 怎么保证 oracle 不会和主实现共谋同一个 bug？**
**A**：四条独立：不同算法（朴素枚举 vs 动态规划）、独立子进程、
仅标准库、AST 级 import 隔离 + monkeypatch 破坏测试。
**展开**：加第三重保险——**精确算术对齐**：所有概率用分数表示，
12 个冻结问题上主实现与两个 oracle 的偏差**精确等于 0**（不是 1e-16 容差）。
而且一旦两边不一致，流程判 INVALID（E002）并停止，不会"选一个信一个"。
**追问**："如果两个 oracle 都错了呢？" → 两个完全不同的算法实现错成同样的
数值，概率极低；而且我还有一个兜底：M0 的 57× 正例和 T003 拒绝这类结论，
都有解析推导（闭式）做过 cross-check（机制理论文档里的三条公式，数值
验证 ==0 偏差）。

**Q8. "机制门"的判定标准是不是你自己定的？会不会过严？**
**A**：标准是**预注册**的——跑实验之前写进协议并内容哈希冻结，不是看到
结果再调。具体判据：自适应映射校准出的参数若与固定对照完全一致（无多样性），
判 MECH001。
**展开**：为了不"拍脑袋"，我还把它升级成了统计检验：D002 的 [2,2,2,2]
落在候选宽度零分布的 **0 分位**（p ≤ 0.05）。过严的风险确实存在，所以我把
结论窄化——只保留"固定映射效率"，把 adaptive 那部分关掉而不是硬留。
**追问**："有没有可能方法本来设置了宽度 2，你误判？" → 预注册的宽度候选
集合包含 {2, 4, 8} 等；方法在校准集上独立选了 4 个问题全选 2，与固定
对照完全相同——这不是我挑的，是它自己选的。

**Q9. V001 的 26.5 倍怎么来的？为什么校准准确还这么差？**
**A**：两个机制。① **1/q 方差放大**：残差校正项要除以采样概率 q，
公式 `Var(ĝ) = Var(R·s)/q + g*²(1/q − 1)`，q 小时两项都爆炸；
② **分支成本**：每次校正要多跑一段对比轨迹，同预算下周期数大幅减少。
期望是对的（校准 1e-16），但固定预算 MSE 中位数 26.5 倍（CI [16.8, 42.9]）。
**追问**："会不会是你的预算设太紧？" → 预算是预注册的，而且我对
"vs dense"和"vs HH"两个基线都报了数（26.5× 和 3.06×），结论方向一致。

**Q10. paired-replay 赢 57 倍的正例是不是调出来的？**
**A**：是**预注册的 designed world**——世界构造、协议、种子在跑之前冻结
（决策日志 D8/D9）。但我做了两件事让它有意义：① 有对照组——把配对耦合
去掉的 uncoupled 版本**输 dense 7 倍**，说明赢的是"配对机制"而不是世界
本身好赢；② 讲的时候主动区分 designed vs discovered。
**追问**："为什么配对能赢？" → 配对让"同前缀的两个分支共享后缀噪声"，
对比量的方差被消掉一大块（机制理论里有闭式方差公式）；dense 虽然无偏，
但每个周期方差大，固定预算下反而吃亏。

**Q11. 执行过程中最大的难题是什么？怎么解决的？**（高频，准备充分）
**A**：Stage 3 的真实闭环。三个具体难题：
① **vLLM 在两台服务器都起不来**——一台是 Blackwell 新架构（SM 12.x 要求
更新的 CUDA 运行时），另一台环境冲突。我改成**训练器自身采样 + Guard 的
`exact_behavior_scorer` 模式**（schema §7.5：训练器生成并精确打分自己的
样本），并把"未使用 vLLM 生成服务"作为限制写进每个 run 的 metrics.json。
② **显存 OOM**——256 条序列一次前向的 float logits 约 31GB（16 条一 chunk
也有 8+GB 峰值）。我改成**分块反向传播**：每 8 条算一次 loss 立即 backward，
梯度累加，峰值降下来；40GB 卡（A800）也能跑。
③ **共享服务器资源争抢**——别人的实验随时抢卡，我的训练被 kill。
我写了**带 GPU 门控的自愈启动器**：启动前扫描显卡占用（只捡 ≤1GB 的
空闲卡，优先指定卡序）、检测到他人进程就等待重试、被中断后**断点续跑**
（已完成的 run 自动跳过，用 metrics.json 存在性判断）。
**追问**："你怎么知道不是你的代码 bug？" → 因为我做了最小复现：本地 8
prompt 单 epoch 的 smoke 先跑通，再推到 32×8×3 的完整配置；OOM 是 CUDA
报错精确定位的；被 kill 是 rc=137（SIGKILL）而不是异常退出——能区分
"我的 bug"和"环境问题"。

**Q12. 在共享服务器上怎么保证不干扰别人？**
**A**：四条纪律：① 只用显存占用 ≤1GB 的空闲卡；② 一次只用一张卡；
③ 检测到别人的进程就睡 5 分钟重试，绝不抢；④ 重活优先 CPU。
**展开**：实际的 18 次训练期间，另一个用户的模型评测（占 3 张卡）同时在跑，
两边互不干扰——我的每次训练只占 1 张空闲卡、约 20-40 分钟。
**追问**："如果所有卡都被占了？" → 启动器进入等待循环（每 5 分钟检查
一次），不发起任何抢占行为；我的预算和项目性质（CPU-first）允许我无限期
等待而不损失什么。

**Q13. paired 门 9/9 弃权——是 bug 还是发现？怎么排除 bug？**
**A**：是发现。三层排除：① **单元测试**覆盖了门的三态（OK /
NO_RELIABLE_CREDIT / DEGENERATE_GROUP），逻辑正确；② **同环境对照**——
同一批次里 dense/local 正常更新（梯度范数 ~4.9），说明不是框架问题；
③ **原因可解释**——58% 的样本产出无效工具调用，效用矩阵太平，统计上
不可靠，所以门选择弃权。
**展开**：这正是预注册预测 4 说的"门会关"；但"后期恢复"没发生——我
如实报告了预测部分被证伪（也有对应的判定：P4 partial）。
**追问**："那这个方法是不是没用？" → 不能这么推。它在"有可靠信号"的
场景下（比如信号稳定的任务）门会开；这里给出的是**边界条件**：当基础
模型能力不足、数据一半无效时，保守门会全程关闭。这正是审计要暴露的东西。

**Q14. tau2 任务全部零奖励，为什么不换个任务重跑？**
**A**：两个原因。① 换到"满意为止"就是**挑结果**，违反预注册纪律
（D002_TEST_TIME_RESElection 正是我要防的行为）；② 这个负结果有信息量：
它量化了"基础模型 + 稀疏奖励任务"的冷启动问题。
**追问**："那你从中学到什么？" → 这类任务需要先做**格式预热**（让模型
学会输出合法调用）再上 credit 训练；我把它写进了 Stage 3 报告的分析里，
也是"下一步"的第一项。

**Q15. 怎么保证结果可复现、没有选择性报告？**
**A**：四条：① **协议冻结**——协议 JSON + 种子清单跑前内容哈希；
② **no-overwrite**——canonical 输出拒绝覆盖，重跑必须新目录；
③ **证据链**——数字 → artifact + commit + SHA256SUMS；
④ **fresh-clone 复现**——CI 有一条从干净克隆一键复现 M0 的流水线。
选择性报告的对策是**全量上报**：V001 的效用失败、D002 的机制失败、
Stage 3 的门弃权和零奖励任务，全部在 README 和 REPORT 里，不藏。
**追问**："决策日志是什么？" → 每次偏离原设计的决定（比如 D10 删除
v0.1.5 证据包、D13 换采样方式）都要记录：决定、证据、替代方案、为什么
拒绝、可证伪条件。附在仓库里，任何人都能查。

### C 组：工程与协作（Q16-Q22）

**Q16. 这个项目的技术栈？**

**Q17. 你写了多少代码？**

oracles/audit/adapters/experiments/report）+ 测试 234 个用例 + stage3 训练

**追问**："最难写的是哪部分？" → 独立 oracle 的隔离（要保证它真的不 import
被测代码，我用 AST 静态分析 + monkeypatch 破坏测试来证明）+ 机制门
（要先想清楚"机制为假会留下什么指纹"）。

**Q18. 项目里你犯过的错 / 最大的教训？**（几乎必问，准备最充分）
**A**：三个层次，由浅入深：
① **工程事故**：v0.1.5 发布后，Linux 上 73/98 个校验和对不上。根因是
换行符——Windows 用 CRLF，哈希是在 CRLF 上算的，Git 存的是 LF。修复：
`.gitattributes` 统一 LF + 写入端显式 LF + CI 加"发布物必须通过自己审计"
的门。教训：**跨平台/证据类问题要在 CI 上用目标平台验证**。
② **自己方法的假结果**：D002 的 adaptive claim 是我自己想要的卖点，
被自己的机制门否决。教训：**标准要在看结果之前定**——正因为预注册，
我才会认。
③ **执行层面的教训**：在共享服务器上，反复的 ssh 超时调用在服务器上留下
了"幽灵启动器"（后台进程持续排队重试），互相干扰导致矩阵反复失败。
后来改成"一个启动脚本 + 进程扫描验证 + 断点续跑"。教训：**远程执行要有
幂等的启动和可观测的状态**，不能靠"再试一次"。

**Q19. 如果给你 10 倍算力，你会做什么？**
**A**：三件事。① 把 Stage 3 规模做大（更多 epoch / 更大 LoRA rank），让
最终评估指标真的动起来——那样就能检验"机制级判断能否预测效果级排序"；
② 给 tau2 类稀疏任务加"格式预热阶段"，量化预热对 credit 信号的影响；
③ 在真实轨迹上做全部六类故障注入（现在是在冻结 fixture 上做的）。
**追问**："为什么不做更多方法？" → 我不想变成"又一个跑分工具"；
先把三类结论（无偏/失败/机制退化）在真实场景里打通，比加方法更有价值。

**Q20. 这个项目最难的技术点？**
**A**：**机制的独立验证**。测偏差有标准做法（对 oracle），但"正结果真的
来自声称的机制吗"没有现成标准——你得先想清楚"如果机制是假的会留下什么
指纹"，再设计检查。我的答案：让方法自己校准参数，然后把参数摊开对比
固定对照；[2,2,2,2] 就是这么抓到的。

**Q21. 这个工具在工业界有什么用？**
**A**：两个直接场景。① **训练管线回归防线**：任何新的 credit/advantage
方法上线前先做三件事——target 澄清、成本匹配、机制检验，避免"指标涨了
但机制没生效"；② **轨迹审计**直接可用：检查 optimizer 实际消费的数据
（mask 对齐、policy 版本、日志概率绑定）——这些 bug 在生产训练里非常
常见且隐蔽，我的 Guard 项目就是在真实环境里抓到过这类问题的。
**追问**："能开源给团队用吗？" → 可以，MIT 协议；接入方式是写一个估计器
插件（实现一个固定接口）+ 一个协议 JSON。

**Q22. 你和其他人怎么协作？（如果你提过 Guard 是另一项目）**
**A**：两个仓库是同一个人的两个项目，但设计上互相独立：schema 归属清晰
（Guard 拥有 envelope schema，我不 fork）、接口用 hash 引用、fail-closed。
这也是我理解的工程协作原则：**边界清晰 + 接口稳定 + 失败可检测**。

### D 组：陷阱与压力题（Q23-Q30）

**Q23. 你的结果能推广到真实 LLM 训练吗？**
**A**：能推广的是**方法**（审计流程、预测公式、故障分类），不能推广的是
**数字**（有限世界的偏差/MSE 不等于真实任务的收益）。Stage 2/3 就是为
"方法能不能迁移"这个问题设计的，结论是"预测公式在可控世界里成立
（0.87-1.07），真实闭环里流程跑通但最终指标未变"。

**Q24. 那你这个项目到底证明了什么？**
**A**：三件事。① 审计流程本身可行且自动（四道门 + 23 个 reason code +
13 类故障回归）；② 一批具体方法性质被量化（无偏/有偏/机制退化）；
③ 从精确到采样的**预测关系**成立（0.87-1.07，误差 <13%）。

**Q25. 你这个 1e-16 是不是浮点噪声？为什么不用符号计算？**
**A**：1e-16 是**双精度浮点在比较"分数精确值"时**的表示极限；关键是
我用的是 Fraction（有理数）做核心计算，"mismatch == 0"是**精确的零**。
1e-16 出现在需要转成浮点的展示层（例如偏差的数值打印）。符号计算
（sympy 类）没有必要——Fraction 已经是精确有理数运算。

**Q26. 为什么用 10^7 这个规模？怎么保证不是伪收敛？**
**A**：5k → 100k → 10M 是三档跨两个数量级；reversal 率 2.88% → 3.244%
→ 3.2744% 单调收敛且幅度递减，且 10M 的 ±0.006pp 区间与 100k 的结果重叠。
"伪收敛"的风险靠两点规避：① 每档都是全量精确统计（不是抽样）；
② 家族生成和判据在协议里冻结。

**Q27. 如果我给你一个真实训练日志，你能审计吗？**
**A**：能审的是**结构性故障**（这部分我已有工具）：mask 与 token 长度
不一致、日志概率长度不符、策略版本缺失/混用、估计器掩码与优化器消费
掩码不一致、记录不可解析。不能直接审的是"这个方法有没有偏"——那需要
真值（oracle）或受控环境。所以流程是：先用轨迹审计清掉数据层问题，
再在受控环境里审方法层问题。

**Q28. 你的方法和 RLHF/GRPO 里的 advantage 归一化冲突吗？**
**A**：不冲突——审计的是"估计的量对不对、预算公不公平、机制真不真"，
归一化只是 target 定义的一部分。如果归一化改变了 estimand（例如 group
标准化让目标依赖同批次的其它样本），那正是 T001/T002 要问的问题：
你要估的量到底是什么、偏差可不可解释。

**Q29. 这个项目对你个人成长最大的是什么？**
**A**：学会**在被结果诱惑时不改标准**。预注册、decision log、claims
政策这些东西，写起来麻烦，但正是在 D002 那种时刻——我自己的方法指标
赢了、机制输了——让我能做出正确处置而不是自我欺骗。

**Q30. 你有什么问题问我们？**（反问环节，准备 3-5 个）
- 团队现在训练管线的"回归防线"是怎么做的？有没有针对 credit/advantage
  变更的自动化体检？
- 你们更看重"新方法带来收益"还是"把已有方法的可靠性说清楚"？
- 如果我要把轨迹审计工具接到你们的训练栈上，第一步应该对接什么数据？
