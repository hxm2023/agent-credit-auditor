## 1. 三段讲稿（背熟，按时间场合选用）

### 1.1 30 秒版（自我介绍里被追问时）

> 我做 GRPO 的 agent credit assignment 时，拿到一条 36.5%→63.5% 的成功曲线，
> 审计发现线上 rollout 的 policy 根本没跟着 trainer 更新——曲线测的是一个
> 从未进化的旧模型。我没有继续调模型，而是建了这个审计工具：逼每个 credit
> 估计方法回答四个问题——在估什么、有没有偏差、同预算下值不值、机制是不是
> 真的。它在精确可枚举的小世界里验证到 1e-16，再桥接到真实训练闭环，抓出过
> 传播式估计期望为零、校准准确但差 26.5 倍、自适应实际退化成固定值这些假货。

### 1.2 3 分钟版（主动讲项目时）

**钩子**：36.5%→63.5% 的曲线是假的——rollout policy 静态不更新，测的是旧模型。

**动机**：这个领域不缺新方法，缺"验证方法是真的"的标准。我把自己踩的坑
拆成一道题：任何 credit assignment 方法必须过四道门。

**装置**（四道门）：
1. **Estimand**：说不清在估什么 → 在精确小世界里算到数学精确。
   *抓到*：把局部对比传播到共享前缀的方法，传播部分**期望精确为 0**。
2. **Bias**：两个独立 oracle（路径枚举 + Bellman DP，独立进程、零共享代码）
   验证到 **mismatch == 0**（用分数精确算术，不是容差）。
   *抓到*：ρ=0.735 的相关性是在"根本没有方差"的数据上算的。
3. **Cost**：所有方法记同一本成本账，同预算比 MSE。
   *抓到*：一个校准误差 1e-16 的方法，固定预算 MSE 差 dense **26.5 倍**。
4. **Mechanism**：把校准出的参数摊开看。
   *抓到*：一个"自适应可变宽度"方法指标赢 5 倍，但宽度全塌缩成 **[2,2,2,2]**
   ——和固定对照完全一样。我主动关掉了它的 adaptive claim。

**桥接**：精确领域再漂亮也要证明能预测真实。我造了可控的 tool-agent 世界，
exact 层的预测公式（方差×成本÷预算 + 偏差²）复现真实采样 MSE 的比率落在
**0.87-1.07**（误差 <13%）。

**闭环**：在共享 8×A800 上跑完 **18 次** Guard 监督的真实 GRPO 训练
（2 任务 × 3 估计器 × 3 seeds，Qwen3-4B + LoRA）。发现：dense/local 每轮
真实更新（grad_l2 ~4.9）；paired 分支的可靠性门 **9/9 全部弃权**（零更新
而不是瞎更新）；第二个任务全部零奖励（诚实负结果）。全部轨迹过离线审计：
768 条/run，零违规。

### 1.3 10 分钟版

按 `docs/tech_narrative.md` 的 Act 1-7 讲。**两处必须主动说**：
- **Act 5（designed vs discovered）**：哪些正例是预注册设计的探针（M0 的
  57×、D002 的 pass），哪些是真实发现（dense 无偏、V001 失败、传播有偏）。
- **Act 7**：Stage 2 的桥 + Stage 3 的闭环，包括"门弃权"这个不讨喜但诚实的
  结果。

## 3. 技术架构（白板讲解顺序）

```
① 精确世界（可枚举的小 MDP）
   所有路径 × 概率 × 奖励 → 用 Fraction 精确算期望/方差
   例：4 步决策，每条路径概率 1/16 这种精确分数

② 独立 oracle（两个，不同算法、独立进程、零共享代码）
   枚举法：把路径一条条列出来加总
   Bellman DP：从终点倒推
   两者一致 → 目标可信；不一致 → 实验判 INVALID

③ 估计器插件（被测对象）
   输入：轨迹；输出：梯度/信用估计
   同一个接口，dense / local sibling / paired-replay / PC-RSG 都可以插入

④ 四道门（审计）
   T 系列：目标身份（你在估什么）
   S 系列：采样支撑（数据里有没有这个量）
   C 系列：成本匹配（预算公平）
   MECH 系列：机制验证（自适应真的自适应吗）
   任何一门 FAIL → 该 claim 被否决（这是正确结果，不是软件错误）

⑤ 桥接与闭环
   exact → 采样（预测公式验证）→ 真实训练（18 次 GRPO，Guard 监督）
```

## 4. 21 个高频拷问 + 应答

### A. 定位与意义类

**Q1. 一句话说这个项目是干什么的？**
A：给 agent RL 的 credit assignment 方法做审计的工具。它不是新算法，是
一套"逼每个方法回答四个问题"的验证系统：估什么、偏不偏、值不值、机制真不真。

**Q2. 不出新算法、没有 SOTA 数字，价值在哪？**
A：这个生态里最大的问题不是方法少，是"漂亮曲线"和"真实效果"经常脱节——
我自己就踩过：静态 rollout 的假曲线。我做的是**把这种判断标准化、可复现化**。
价值在判别力：我用它抓出过期望为零的传播、校准准但差 26.5 倍的方法、
退化成固定值的"自适应"。这些结论对任何做 credit assignment 的人都有用。

**Q3. 你自己方法被这个工具否决过吗？**
A：有，而且这是最有说服力的部分。D002 那个方法的 adaptive claim 是我自己的
路线，被自己的机制门否决后我主动关掉了 claim，只保留"固定映射效率"的窄结论。
另外自审计还抓出我 3 个对照组构造 bug。

### B. 方法论深挖类

**Q4. 精确小世界不是玩具吗？跟真实 LLM 有什么关系？**
A：分三层回答。第一层，小世界的**价值是可控**——能精确算 bias，这在真实
场景做不到（真值未知）。第二层，我做了**证据桥**：在可控世界验证"精确层的
预测公式能预测采样层的 MSE"，比率 0.87-1.07。第三层，**真实闭环**：18 次
真实 GRPO。我不声称小世界代表真实分布——我声称的是**这套判断方法能迁移**，
并且我用实验验证了这个迁移。

**Q5. 怎么保证 oracle 不会和主实现共谋同一个 bug？**
A：三重独立：**不同算法**（朴素枚举 vs 动态规划）、**独立进程**（子进程、
stdlib-only、AST 级 import 隔离）、**破坏性测试**（monkeypatch 测试证明
隔离有效）。再加 Fraction 精确算术对齐：12 个冻结问题上三路结果**精确相等**
（mismatch == 0，不是 1e-16 容差）。共用 bug 要同时骗过两个完全不同算法的
实现，概率极低；而且真出现不一致时系统判 INVALID 而不是继续。

**Q6. "机制门"的判定标准是不是你自己定的？会不会过严？**
A：标准是**预注册**的——在跑实验之前写进协议并哈希冻结，不是看到结果后
调的。具体判据：自适应映射校准出来的参数如果和固定对照完全一致（无多样性），
就判机制失败（MECH001）。D002 的 [2,2,2,2] 还做了统计检验：落在候选宽度
零分布的 0 分位。过严的风险确实存在——所以我把结论窄化，不推广。

**Q7. V001 的 26.5 倍怎么来的？为什么校准准确还这么差？**
A：两个原因。① **1/q 方差放大**：那个方法在每个决策点做残差校正，校正项
要除以采样概率 q，q 小时把噪声放大很多倍；② **分支成本**：每次校正要多跑
一段对比轨迹，同预算下能跑的样本数大幅减少。所以它的期望是对的
（校准误差 1e-16），但有限预算下 MSE 中位数是 dense 的 26.5 倍
（bootstrap CI [16.8, 42.9]）。这正是"校准准≠好用"的量化证据。

**Q8. paired-replay 赢 57 倍的正例是不是调出来的？**
A：这是**预注册的 designed world**——世界构造、协议、种子在跑之前冻结
（决策日志 D8/D9）。但我做了两件事让它有意义：① 有对照组——把配对耦合
去掉（uncoupled），对照组输 dense 7 倍；说明赢的是"配对机制"而不是世界
本身好赢。② 我在讲的时候主动区分 designed vs discovered。

**Q9. 什么是 K-sample prefix floor？**
A：共享前缀的估计器有一个方差下限：不管你对后续分支采样多少样本，
共享前缀上的方差（Var(E[g|prefix])）消不掉。所以"加宽采样"这类方法在
固定预算下有一个够不到的天花板。这是我用闭式推导算出来的（数值验证
== 0 偏差），也解释了为什么某个历史数字（0.694）在正确协议下无法复现。

**Q10. 精确算术和 1000 万规模怎么兼容？**
A：普查实验用分数精确算术（Fraction），10M 家族在 48 核上 88 秒跑完，
零 GPU。关键在于：每一族的计算量是常数级，并把并行粒度做在家族层面。
分数算术比浮点慢，但在这个问题规模下完全可接受，换来的是"没有舍入误差"
的确定性结论。

### C. 执行与工程类

**Q11. 执行过程中最大的难题是什么？**
A：Stage 3 的真实闭环。三个具体难题：
① **vLLM 在两台服务器都跑不起来**——一台是 Blackwell 新架构（SM 12.x
要求更新的 CUDA），一台环境不兼容。我改成用 trainer 自身采样器 + Guard 的
`exact_behavior_scorer` 模式（训练器自己生成、自己精确打分），并把"未使用
vLLM 生成服务"作为限制如实写进每个 run 的 metrics。
② **显存 OOM**——256 条序列一次前向的 float logits 高达 31GB。我做了分块
反向传播（每 8 条一个 chunk 单独 backward），把峰值压下来。
③ **共享服务器的资源争抢**——别人的实验随时抢占 GPU，我的矩阵被杀。
我写了带 GPU 门控的自愈启动器：只捡空闲卡（≤1GB 占用）、一次一张、被占用
就等待重试、断点续跑（已完成的 run 自动跳过）。

**Q12. 在共享服务器上怎么保证不干扰别人？**
A：四条纪律：① 只使用显存占用 ≤1GB 的空闲卡（优先指定卡序 6/7/4）；
② 一次只用一张卡；③ 检测到别人的进程就睡 5 分钟重试；④ 全部 CPU-first
的重活优先本地/CPU 核。实际的 18 次训练全程，别人的实验（另一个用户的
模型评测）同时在跑，互不干扰。

**Q13. paired 门 9/9 弃权——是 bug 还是发现？怎么排除 bug？**
A：是发现，并且我做了三层排除：① **本地单测**复现了 gate 的三种状态
（OK / NO_RELIABLE_CREDIT / DEGENERATE_GROUP），逻辑正确；② **同时跑的
dense/local 在同一环境下正常更新**（grad_l2 ~4.9），说明不是框架问题；
③ 弃权的原因是数据本身：58% 的样本产出无效工具调用，效用矩阵太平，
统计上不可靠。这正是预注册预测 4 说的"门会关"——只是"后期恢复"没发生，
我如实报告了预测部分被证伪。

**Q14. tau2 任务全部零奖励，为什么不换个任务重跑？**
A：两个原因。① 换任务重跑到满意为止，就是在**挑结果**——违反预注册纪律；
② 这个负结果本身有信息：它量化了"基础模型 + 稀疏奖励任务"的冷启动问题，
任何人在这个组合上做 credit assignment 都会遇到。诚实的负结果比挑选后的
正结果可信。

**Q15. 怎么保证结果可复现？**
A：四件套：① **协议冻结**——JSON 协议 + 种子清单跑前内容哈希，任何改动
走决策日志版本升级；② **no-overwrite**——canonical 输出拒绝覆盖，重跑必须
新目录；③ **证据链**——每个数字追溯到 artifact 目录 + git commit +
SHA256SUMS；④ **fresh-clone 复现**——CI 里有一条从干净克隆一键复现 M0 的
流水线。

**Q16. 数字怎么保证没有选择性报告？**
A：预注册 + 全量上报。预注册：每个实验的主指标、门限、判据在跑之前冻结。
全量上报：失败结果照样进报告——V001 的 MSE 失败、D002 的机制失败、
Stage 3 的门弃权、tau2 的零奖励，全部在 README 和 REPORT.md 里。claims
政策还规定了"哪些话不许说"（见第 5 节）。

### D. 深度与前瞻类

**Q17. 这个项目最难的技术点？**
A：我认为是**"机制的独立验证"**。算 bias 有标准做法（对 oracle），但验证
"正结果真的来自声称的机制"没有现成标准——你得先想清楚"如果机制是假的，
会留下什么指纹"，再设计检查。我的做法是：让方法自己校准参数，然后把参数
摊开对比固定对照。D002 的 [2,2,2,2] 就是这么抓到的。

**Q18. 如果给你 10 倍算力，你会做什么？**
A：三件事。① 把 Stage 3 的规模做大（更多 epoch、更大 LoRA rank），让 final
eval 真的动起来——那样就能验证"机制级判断"能否预测"效果级排序"；② 把
tau2 类稀疏任务做成"冷启动预热 + 训练"的对照，量化奖励稀疏度的影响；
③ 在真实轨迹上复现 Stage 1 的全部六类故障注入（现在是在冻结 fixture 上）。

**Q19. 你这个项目和你另一个项目（GRPO-Guard）什么关系？**
A：一条信任链的两半。Guard 管**在线**：保证生成轨迹的模型身份、token/mask、
日志概率、权重同步都是真的。Auditor 管**离线**：即使轨迹是真的，也要审计
"估计器声称的东西"是不是真的。两个仓库互相引用：Guard 签发的轨迹
envelope 流进 Auditor 的校验（hash-only、fail-closed 钉在 Guard 的 schema
版本）；Stage 3 的 18 次训练就是 Guard 监督训练、Auditor 审计轨迹。

**Q20. 这个项目有哪些明确的边界？**
A：三条。① 不证明真实 LLM 下游收益——Stage 3 的 final eval 没变（3 步小
LoRA 本来就是机制级实验）；② 精确世界不外推到真实任务分布；③ 历史数字
（144/202、0.694、ρ=0.735）只当事故背景，从不作为复现结果。主动说边界
比被问出来好。

**Q21. 这个工具在工业界有什么用？**
A：最直接的场景是**训练管线的回归防线**：任何新 credit/advantage 方法进
生产线前，先用这套做 target/成本/机制三项体检，避免"指标涨了但机制其实
没生效"。另外 trajectory 审计那部分直接可用：检查 optimizer 实际消费的数据
（mask 对齐、policy 版本、日志概率绑定），这些 bug 在生产训练里非常常见
且非常隐蔽——我的 Guard 项目就是在真实环境里抓到过这类问题的。

## 6. 现场白板脚本（5 分钟画完）

1. **画一条曲线**：36.5% → 63.5%，旁边打一个红叉，写"rollout 是静态的"。
2. **拆两个框**：左"Guard（在线）"，右"Auditor（离线）"，中间画一条
   "轨迹 envelope"的箭头。
3. **四道门**：画四扇门，每扇门下面写一个抓到的假货
