## 0. 速查卡（进考场前 5 分钟）

**一句话**：给 credit assignment 方法做审计的工具——不是新算法，是逼每个
方法回答四个问题的验证系统。

**四道门 + 四个抓到的假货**：

| 门 | 抓到的假货 | 数字 |
|---|---|---|
| Estimand（在估什么） | 局部对比传播到共享前缀 | 期望**精确为 0** |
| Bias（偏不偏） | ρ=0.735 的假方差（在无方差数据上算的） | 双 oracle：1e-16 |
| Cost（值不值） | 校准准确但固定预算失败 | MSE **26.5×** CI [16.8, 42.9] |
| Mechanism（机制真不真） | "自适应"实际是固定宽度 | 宽度 **[2,2,2,2]** |

**必背六数字**：
1. **1e-16 / ==0**：dense 无偏；主实现与双 oracle 精确一致
2. **期望 = 0**：传播式估计（T003 拒绝）
3. **26.5×**：V001 校准准但差（CI [16.8, 42.9]）
4. **[2,2,2,2]**：D002 自适应塌缩（p≤0.05 统计检验）
5. **0.87-1.07**：exact 层预测真实采样 MSE 的比率（误差 <13%）
6. **18/18 + 9/9 弃权**：真实闭环 18 次训练；paired 可靠性门全程弃权

**三个亮点故事**：假曲线（静态 rollout）→ 双裁决（指标赢机制输）→ 真实
闭环（门弃权 + 零奖励负结果）。

**一句诚实的边界**：不声称真实 LLM 收益提升——最终评估指标没变，这是
机制级实验。

## 2. 背景速成（给完全不懂的人讲）

### 2.1 大模型怎么训练（GRPO 是什么）

大模型不是写代码写出来的，是"练"出来的。主流练法之一 **GRPO**
（Group Relative Policy Optimization，组相对策略优化）可以用驾校教练类比：

1. **让模型自己开一遍车**——生成一段回答，或执行一个多步任务（查资料、
   下单……）；
2. **给这次表现打分**——任务成功 = 高分，失败 = 低分；
3. **调整模型**——让"得高分的做法"以后更容易出现。

术语对应：
- **policy（策略）** = 模型本身：给定当前上下文，决定"下一步做什么"的
  概率分布；
- **rollout（采样/展开）** = 让模型真的走一遍、把过程记下来；
- **reward（奖励）** = 任务结束后的分数；
- **trainer（训练器）** = 根据数据更新模型权重的那部分程序。

### 2.2 credit assignment 是什么

一段 200 字回答，模型其实逐词做了 200 次小决定；最后只给一个总分。
**问题：这 200 个决定里哪些好、哪些坏？功劳怎么分？** 这就是 credit
assignment（信用分配）。

**具体例子**：训练"订票助手"，动作序列是
`① 查余票 → ② 选航班 → ③ 填乘客信息 → ④ 支付 → ⑤ 出票`。
订票成功了——功劳在②（选对航班）还是④（支付顺利）？如果④之前系统
自动纠正了③的错误，模型可能学到"填错身份证也没关系"的坏习惯。

### 2.3 这个项目要解决的真问题

领域里有几十种 credit assignment 方法，每篇论文都声称更好。但我自己踩过
一次事故：

**我拿到 36.5% → 63.5% 的漂亮曲线，最后发现生成数据的 rollout 一直用的是
程序启动时的静态模型副本——训练器在更新权重，采样器没有跟着换。**
曲线测的是一个从未进化的旧模型。类比：**你测试了三个月的健身方案，
最后体检的是三个月前的你自己。**

这个事故说明：**这个领域缺的不是新方法，是"验证方法是真的"的标准。**
所以我没有继续调参，而是建了这台"质检台"。

### 3.6 核心工作展开版（面试官问"你具体做了什么"时用这个）

完整展开成四块，每块都说清"解决什么问题 → 怎么做的 → 为什么难 → 例子"。

**30 秒压缩版（时间紧时先说这个，再按需展开）**：

> 我的核心工作有四块：一，把"这个方法好不好"从看学习曲线，拆成四道
> 可自动执行的检查（目标、偏差、成本、机制），每道配失败原因码；二，
> 造一把绝对准确的尺子——答案可精确计算的小世界，而且用两个互不引用
> 对方的独立计算器交叉验证这把尺子自己；三，把小世界的判断延伸到真实
> 训练：先证明预测能力（预测/实测比值 0.87-1.07），再跑完 18 次带在线
> 监督的真实训练闭环；四，把"可信"做成工程机制——协议跑前冻结、输出
> 不可覆盖、每个数字可追溯，还给审计器自己做故障注入测试。

**第一块：把"判断方法好不好"从看曲线变成可执行的机器。**
这个领域通常靠学习曲线判断方法好坏，但曲线会被与方法无关的因素左右
（我就踩过：采样模型没更新，曲线测的是旧模型）。我的工作是把它拆成
四道可执行检查，每道配失败原因码：① 目标检查——要求方法用结构化文档
声明"估的是什么"（完整梯度/局部效应/其他），声明完我用数学核对；
② 偏差检查——需要一个绝对准确的参照（第二块）；③ 成本检查——给和基线
完全一样的预算比精度（防"多花三倍算力换一点精度"）；④ 机制检查——变好
的原因真是声称的机制吗。四道门都有代码、23 个具体原因码（T003 =
非法传播、MECH001 = 自适应塌缩）、配套回归测试。任何方法接进来跑完就
得到结构化体检报告。

**第二块：造一把"绝对准确的尺子"（工程量最大）。**
真实训练没有正确答案可查，所以我造了答案已知的小世界：4-6 步决策、
每步两个选择，全部走法最多几十条——每条都能列出来算概率和得分，
"平均结果"可以精确算出。所有概率用**分数**（3/8 而非 0.375）计算，
没有舍入误差，"偏差 = 0"是字面意义的 0。防"标准答案自己也错"：
做了两个**互相独立**的计算器——一个最笨的（枚举所有路径加总）、一个
聪明的（从终点倒推），不同算法、独立进程、只用标准库，还写静态检查
确保算答案的程序不引用被测方法代码（否则会复制同一个 bug，审计变成
自己批自己）。三方必须精确一致，否则实验判无效。

**第三块：从小世界延伸到真实训练——两级台阶。**
第一级"证明预测能力"：小世界里能精确算出每种方法的预计误差；再造一个
中等规模可采样的工具调用环境（上一步结果影响下一步决策概率），用同样
方法在采样数据上跑、测实际误差——**预测/实测比值 0.87-1.07（误差 <13%）**。
意外收获：一个方法在独立决策世界里无偏，换到"结果影响后续决策"的结构
就有偏——漏算了"决定→未来观察→未来决定"的**间接影响链**，只有精确
计算能暴露。第二级"真实训练闭环"：带在线监督的训练流程（身份校验 →
打分 → 更新前审批 → 更新 → 提交 → 验证），共享 GPU 上完成 **18 次真实
训练**（2 任务 × 3 方法 × 3 种子，40 亿参数模型微调一小部分参数），
数据再过离线质检；不讨喜的结果照实报告（保守门 9/9 弃权、一个任务全零
奖励）。

**第四块：让"可信"靠机制不靠自觉。**
协议与种子跑前冻结并哈希（改动=新版本）；输出不允许覆盖（重跑必须新
目录）；每个数字记录在三件套（产物目录 + 代码提交 + 校验和）；
CI 里有一条"发布物必须通过我自己的审计"；给审计器做**故障注入测试**
（故意注入 13 类错误，验证每次都报出正确原因码）——这个过程真抓出
我自己 3 个 bug。

**第一段：AI 是怎么"学"的（1.5 分钟）**

把 AI 模型想象成一个**学徒**。训练办法：让他做任务 → 给结果打分 → 他根据
分数调整自己，让"得分高的做法"下次更容易出现。例子：训练"订票助手"，
用户说"帮我订张去北京的票"，助手做一串动作：
`① 查余票 → ② 挑航班 → ③ 填乘客信息 → ④ 支付 → ⑤ 出票`。
整套下来只有一个结果：订成功了，或没成。
记住三个词：**学徒（模型）、一串小决定（动作序列）、最后的分数**。

**第二段：核心难题——功劳怎么分（1.5 分钟）**

五步动作只有一个总分：**订成功了，功劳算谁的？** 是第②步挑对航班？还是
第④步支付顺利？如果第③步身份证填错、但被系统自动纠正了，助手会不会学到
"填错也没关系"？"把总分合理分到每一步"就是**信用分配**。关键点：**分错了，
学徒就学坏。**

**第三段：我出的那场事故——曲线是假的（2 分钟）**

我得到一条漂亮曲线：成功率 **36.5% 涨到 63.5%**。后来检查一个基础问题：
**打分用的是哪个版本的助手？** 答案是程序启动时那个**旧助手，从头到尾没换过**。
打比方：**你测试健身方案练了三个月，最后体检拿的是三个月前的照片。**
我的决定：**停下来，不追假曲线**——这个行业缺的不是新方法，是"怎么验证
一个方法是真有效的"。于是我建了这台**给信用分配方法做质检的机器**。

**第四段：四道质检门（2.5 分钟，全场核心）**

- **第一道门：你测的东西对啊？** 好比说"我要减肥"——减体重还是减体脂？
  方向错了努力全白费。我要求每个方法先写清"我在算哪个量"，再拿数学核对。
  **抓到的案例**：一类方法把"某一步的功劳"传播到前面所有步骤——**数学上
  等于零**，它在朝一个不存在的方向努力。
- **第二道门：你的答案偏不偏？** 好比尺子开头磨损两厘米，人人量矮两厘米。
  要查偏差就得有**绝对准确的尺子**——真实训练里没有，所以我自己造了一个
  **有标准答案的小世界**；而且做了**两把独立打造的尺子**（不同方法造、
  互不通气），两把结果不一致就判"实验无效"。
- **第三道门：同样成本你值吗？** 两个学生比成绩，一个请了私教做了三倍题，
  这不算公平比较。训练里更隐蔽：有些方法"多跑几条额外实验、多花三倍算力"
  换精度提升。我的做法：**给所有方法完全一样的计算预算再比谁更准**。
  **抓到的案例**：一个方法"准"得惊人（误差接近零），但同预算下误差是简单
  方法的 **26.5 倍**——"算得准"和"用得起"是两回事。
- **第四道门：你的优点是真的吗？** 好比"智能恒温器"拆开发现永远是固定
  22 度，学习功能没工作。**抓到的案例**：一个"自适应"方法指标赢了 5 倍，
  但参数摊开全是**一样的固定值**（[2,2,2,2]），等于最笨的固定设置。我主动
  关掉了它的"自适应"说法——**而且这是我自己的路线。**

**第五段：从小世界到真考场（1 分钟）**

面试官必问："有标准答案的小世界跟真实训练有什么关系？" 我不辩解，用实验
证明：**第一级**，小世界算出"每种方法预计的误差"，再造一个中等规模可采样
的环境实测——**预测/实测比值 0.87-1.07（误差 13% 以内）**；**第二级**，
在共享 GPU 服务器跑完 **18 次真实模型训练**（2 任务 × 3 方法 × 3 种子），
数据全部过质检。其中一类方法的"安全门"在 **9/9 次运行里都选择不更新**
（它判断信号不可靠，宁可不动）——照实写进报告，没藏。

**收尾（30 秒）**

> 我没能提出更强的新方法，但我把"这个方法好不好"这个模糊问题，变成了
> **四道可以自动执行的检查**，从有标准答案的小世界一路验证到 18 次真实
> 训练。它抓出过别人方法的假，也抓出过我自己方法的假。

---

**背这一条主线**：假曲线 → 建质检 → 四道门 → 真假验证。

**背四个比喻**：
① 减肥：减体重还是减体脂 → 目标要对；
② 磨损的尺子 → 需要两把独立的准尺；
③ 请了私教的学生 → 成本要公平；
④ 恒温器拆开是固定 22 度 → 机制要真。

**背三个数字**：
① **等于零**——一类方法在朝不存在的方向努力；
② **26.5 倍**——一个"准"的方法用起来贵 26.5 倍；
③ **0.87-1.07**——小世界的预测在真实场景里误差 13% 以内。

**万能兜底句**（被追问不会的细节时）：
> "这个细节我回去查一下确切数字；但我记得它的结论是……（说你知道的那一半）"

**三个预判反问**：
- "这不就是玩具吗？" → 小世界的作用不是模拟真实，是**提供标准答案**；
  真实场景没有标准答案就测不了偏差；而且我用 0.87-1.07 证明了它能预测真实。
- "你有自己的成果吗？" → 我没发明新算法，是有意的；这行最缺判断标准。
  我敢关掉自己方法的一个卖点，比多留一个好看数字更值钱。
- "为什么值得做？" → 因为我亲自被假曲线骗过；连自己都能被骗，别人一定
  也需要这套检查。


### 3.8 十分钟技术讲法（面试官懂行版，无比喻）

**时间分配**：0:00 问题定义 / 1:30 事故 / 2:30 四问 / 4:00 技术装置 /
6:00 三个主实验 / 7:30 证据桥 / 8:30 真实闭环 / 9:30 边界收尾。

**0:00-1:30 问题定义**
> 这个项目做 GRPO 里 credit assignment 的审计。GRPO 的训练循环是：对每个
> prompt 采一组轨迹，用轨迹级回报算组相对 advantage，做带裁剪的策略梯度
> 更新。结构困难在于 estimand 和信号载体不匹配：优化目标是整条轨迹的策略
> 梯度 `g* = E[R(τ)·Σ_t s_t]`，`s_t = a_t − π_t` 是每步的中心化动作特征
> （logit 参数化下等价于 score function）；但监督信号只有末端标量 R(τ)。
> 把 R 分解到每步决策就是 credit assignment。不同分解给出不同估计量：
> dense、local sibling、paired-replay、PC-RSG 类残差校正——它们在偏差、
> 方差、成本上互不相同，而领域长期只用学习曲线判别。

**1:30-2:30 事故**
> 我拿到过 36.5%→63.5% 的曲线，审计发现三个问题：rollout 侧策略版本没
> 跟随 trainer（采样用启动时的静态 client，behavior policy 与 trainer
> policy 版本不一致）；old_logprob 与行为策略不绑定（算 importance ratio
> 的旧日志概率不是生成轨迹那版策略产生的）；token 序列与 loss mask 身份
> 不闭合。曲线测的是旧 checkpoint 的行为策略。我没继续调参，把问题拆成
> 两个工具：GRPO-Guard 管在线身份与链路，Credit Auditor 管离线估计器。

**2:30-4:00 四个审计问题**
> 一，estimand 是什么（完整梯度/局部效应/root-marginal/continuation
> effect，需结构化声明后数学核对）；二，bias（相对独立 oracle，无偏还是
> 偏差可解释）；三，cost（匹配 transition/intervention 预算下的
> fixed-budget MSE 是否优于强基线）；四，mechanism（正结果是否真来自
> 声称机制）。四类门禁、具体 reason code、冻结判据、回归测试；策略是
> fail-closed，判定失败是**正确的审计结果**不是软件错误。

**4:00-6:00 技术装置**
> 底座是精确可枚举有限 MDP：4-6 步决策、每步二元动作、路径最多 2^6=64
> 条；所有概率与期望用 `fractions.Fraction` 有理数运算，偏差能算到**精确
> 的零**（12 个冻结问题 mismatch == 0）。oracle 双份且独立：朴素路径枚举
> vs Bellman DP，不同算法、独立子进程、stdlib-only；AST 级 import 隔离
> 检查 + monkeypatch 破坏测试；任一侧不一致实验判 INVALID（E002）。
> 估计器经固定接口接入：EstimandSpec（目标）/ SamplingSpec（采样与对比）/
> CostSpec（成本口径含共享成本分摊）/ EstimatorSpec（所需观测与假设），
> 运行前冻结并内容哈希。运行侧 14 步流水线：解析协议 → 校验 → 哈希源与
> 种子 → 拒绝已有 canonical 输出 → split 不相交 → 驱动实验 → 临时包 →
> 原子发布。每个实验目录 7 件套（protocol/result/oracle_result/
> gate_decision/run_manifest/raw_rows/REPORT）+ SHA256SUMS。23 个 reason
> code、13 类故障模板（A1-A14 除 A8）。

**6:00-7:30 三个主实验**
> **M0**：12 个冻结问题，dense 与 uniform-HH 无偏（bias ~1.1e-16）；
> local sibling 对局部效应无偏、对完整梯度有偏；**propagated sibling 与
> BPO-like 被拒**——传播项在 t'<t 上条件均值为零、期望恒等于 0（T003）；
> paired-replay 在预注册 matched-cost 正例上 MSE ratio 0.017 赢 dense，
> uncoupled 对照组输 7.0 倍（增益来自耦合机制）。
> **V001**：PC-RSG 式估计器 20 个校准问题期望误差 ≤1.5e-16，但固定预算
> MSE 中位数 26.53× vs dense（CI [16.78, 42.87]），vs HH 3.06×
> （CI [2.68, 3.30]）；机制是 1/q 放大 `Var = Var(R·s)/q + g*²(1/q−1)`
> 加分支 continuation 成本。
> **D002**：校准集自选 mapping 与 width 并冻结，48 个 held-out 上
> metric PASS（median ratio 0.2054，CI [0.1766, 0.2289]），但选出的 widths
> 全是 [2,2,2,2] = global control（MECH001，零分布 0 分位 p≤0.05）——
> mechanism FAIL，我关闭了该方法的 adaptive claim。

**7:30-8:30 证据桥**
> 构造观察依赖 tool-agent MDP（工具的观察影响下一步动作概率，
> prefix-dependent 策略），小到可精确枚举、大到可采样。同批估计器定义在
> 两层跑：exact 层枚举 cycle 分布（路径 × sibling 抽取，权重精确）；
> sampled 层只消费轨迹记录，匹配预算下测 fixed-budget MSE，参考值为独立
> 高预算 MC（自有随机流与代码路径，不 import 估计器）。结果：预测公式
> `MSE ≈ var_cycle·cost/B + bias²` 复现实测 MSE，比值 **0.87-1.07**。
> Transfer finding：paired-replay 的无偏性在观察依赖世界不成立——按坐标
> 对比漏掉 a_t 经未来观察影响未来动作的间接效应，交叉项 E[Q_t·s_t] 不再
> 为零。

**8:30-9:30 真实闭环**
> 共享 8×A800 上 18 次 Guard 监督 GRPO：2 任务 × 3 估计器 × 3 种子，
> Qwen3-4B + LoRA（rank 16 / alpha 32 / lr 5e-6），每次 32 prompts ×
> 8 generations × 3 epochs。Guard 链路每轮：identity validation → reward
> event → pre-update ALLOW → materialize → guarded update → commit adapter
> → canary。因两台服务器 vLLM 不可用，rollout 改为训练器自身采样 +
> Guard `exact_behavior_scorer` 模式（schema §7.5），限制写进每个 run 的
> metrics。结果：dense/local 每 epoch 真实更新（梯度 L2 均值 4.89/4.86）；
> paired 可靠性门 9/9 弃权（零 credit 零更新）；第二任务有效工具调用率 0、
> 奖励全零、所有估计器零信号；最终评估未变。18 run × 768 条轨迹记录过
> 离线审计，零违规。

**9:30-10:00 边界与收尾**
> 边界：不声称真实 LLM 下游收益（最终评估未变）；精确世界不外推真实分布；
> 历史数字（144/202、24.81x、0.694、rho=0.735）只作事故背景。
> 收束：**把"估计器好不好"的模糊判断替换成四个可执行、可复现、有 reason
> code 的审计门，并用 exact→sampled→real 三层验证证明判断能迁移到真实
> 训练——包括如实报告抓到的失败。**

**讲法提示**：数字后停顿一秒等提问；门禁 code（T003/MECH001/E002）要报；
主动说实现细节（Fraction、AST 隔离、subprocess、no-overwrite、

## 4. 技术解剖（十层）

### 4.1 第一层：精确世界（world families）

**做法**：造"能精确枚举的小型序列决策问题"（MDP，马尔可夫决策过程：
状态→动作→结果→下一个状态的数学模型），4-6 步决策、每步两个动作，
路径总数 = 2^H（H≤6 → ≤64 条），每条路径概率是若干概率的乘积。

**六个世界家族**（代码在 `worlds/`）：
| 家族 | 用途 |
|---|---|
| `bernoulli_sequence` | 伯努利序列 MDP：每步独立动作，用于 M0 目标审计 |
| `d002_shared_logits` | 共享 logit MDP：两个状态共享一个决策参数（用于 D002） |
| `continuation` | continuation 家族：用于 CTRI 诊断与普查 |
| `fraction_world` | 分数精确世界：所有概率/奖励用 Fraction 表示 |
| `tool_agent` | 可控工具智能体世界：观察依赖（上一步调用结果影响下一步概率） |
| `minimal_logging` | 8×3 世界：教学资产（经典 decision-reduct 等价） |

**为什么能"精确"**：路径有限 → 全部列举；概率用**分数（Fraction）**
表示（3/8 而不是 0.375）→ 加减乘除无浮点舍入；于是偏差可以算到
**字面意义的 0**。证据：12 个冻结问题 `mismatch == 0`。

### 4.2 第二层：独立 oracle（防共谋基准）

**两个 oracle，两种完全不同的算法**：
1. **枚举法**：所有路径列出来，概率×奖励加总（暴力但直观）；
2. **Bellman DP**：从终点倒推期望值（动态规划）。

**独立性四条保证**（面试重点）：
- 独立子进程运行；仅用标准库（stdlib-only）；
- **AST 级 import 隔离测试**：静态分析 oracle 代码，证明它不引用被测估计器；
- **monkeypatch 破坏测试**：故意破坏主实现的依赖，验证 oracle 不受影响；
- 不一致 → 实验判 **INVALID**（E002），绝不"选一个信一个"。

### 4.3 第三层：形式化 Schema（项目怎么"说清楚"的）

协议用四个冻结的规范对象描述（`schema.py`）：

| 对象 | 关键字段 | 作用 |
|---|---|---|
| **EstimandSpec** | estimand_id / world_family / policy_parameterization / reward_semantics / continuation_policy / state_conditioning / clipping / discount | 精确声明"在估什么" |
| **SamplingSpec** | decision_sampling / restore / continuation / correction | 数据怎么采、对比怎么建 |
| **CostSpec** | primary_unit / arithmetic / calculator_id / shared_costs / amortization / total_budget_grid / rounding | 成本怎么记账（含共享成本分摊） |
| **EstimatorSpec** | estimator_id / version / claimed_estimand / required_observations / required_assumptions | 估计器声明自己需要什么 |
| **ClaimDecision** | claim_id / claim_text / status / required_gates / gate_results / reason_codes / claim_ceiling | 每个 claim 的裁决与上限 |

**为什么重要**：这四个对象把"口头描述"变成"可哈希、可校验、可比较"的
结构。任何修改 = 版本升级 + 决策日志，不是原地编辑。

### 4.4 第四层：估计器数学（面试官考你的地方）

**符号**：步骤 t 的动作 a_t ∈ {0,1}，行为策略给该动作的概率 π_t。
**分数特征（score）**：
```
s_t = a_t − π_t        （中心化动作指示；logit 参数化下等价于 ∇logπ）
```
**全梯度目标**（要估的量）：
```
g* = E[ R(τ) · Σ_t s_t ]        R(τ) = 整条轨迹的回报
```

**五个被测估计器**：

| 名字 | 公式 | 性质 |
|---|---|---|
| **dense** | `ĝ = R(τ)·Σ_t s_t` | 无偏（偏差 ~1e-16），方差大 |
| **local sibling** | `ĝ_t = (R(τ) − R(τ^{t→a'}))·s_t`，只更新坐标 t | 对"局部效应"无偏；对全梯度**有偏** |
| **propagated sibling** | 同样对比，但更新**所有坐标** | 在 t'<t 上条件均值为零 → **期望恒为 0**（T003） |
| **paired replay** | 每个坐标用自己的对比、**后缀共享（耦合）** | 独立坐标世界里对全梯度无偏 |
| **PC-RSG 类** | `ĝ = R·Σs + (contrast_t − R·s_t)/q_t` | 期望正确（校准 1e-16），方差被 1/q 放大 |

**HH vs HT（抽样加权）**：
- **Hansen-Hurwitz**：有放回抽样 → 权重 = 1/q（选择概率的倒数）；
- **Horvitz-Thompson**：无放回抽样 → 权重 = 1/包含概率（"至少被选中一次"
  的概率）。
- **混用两者 = S003**（在无放回场景用 1/q 会系统性高估）。

**固定预算 MSE 预测公式**（Stage 2 的核心）：
```
MSE ≈ var_cycle · cost / B + bias²
```
每个"估计周期"有固有方差 var、消耗 cost 个 transition、总预算 B →
周期数 B/cost → 均值方差 = var·cost/B；再加偏差²。**预注册预测。**

**K-sample prefix floor（为什么"加宽采样"有天花板）**：
```
Var(ĝ) = E[Var(ĝ|prefix)] + Var(E[ĝ|prefix])
```
第二项只由前缀分布决定，**后缀采多少样本都消不掉** → 共享前缀的方法
有固定预算下的下界。

**HH 的 1/q 放大（V001 失败的数学根源）**：
```
Var(ĝ_HH) = Var(R·s)/q + g*²·(1/q − 1)
```
q 越小（越少采到那个决策）两项都爆炸。

### 4.5 第五层：四道门、23 个 reason code、13 类故障模板

### 4.6 第六层：三个主实验（完整故事）

**M0 — 目标审计**（12 个冻结问题）
- 做法：在精确世界上跑 dense / local sibling / propagated / BPO-like /
  paired-replay，与精确目标比对。
- 结果：dense 与 uniform-HH **无偏**（~1e-16）；local sibling 对局部效应
  无偏、对全梯度**有偏**；**propagated 与 BPO-like 被拒**（T003）；
  paired-replay 在预注册 matched-cost 正例上赢 dense **57 倍**
  （MSE ratio 0.017），去掉耦合的对照组**输 7.0 倍**——赢的是机制。

**V001 — 效用失败**
- 做法：PC-RSG 式残差校正，先验证期望（校准），再比固定预算 MSE。
- 结果：20 个校准问题最大误差 **1.5e-16**（"准"），但固定预算 MSE 中位数
  是 dense 的 **26.53 倍**（CI [16.78, 42.87]），比 HH 也差 **3.06 倍**
  （CI [2.68, 3.30]）。原因：1/q 方差放大 + 分支成本。
- 意义：**"校准准确"≠"好用"**——这是领域里最常见的混淆。

**D002 — 双裁决（旗舰）**
- 做法：校准集上让方法自己选参数（映射 + 宽度），**冻结选择**，再在
  48 个 held-out 问题上测试。
- 结果：**指标 PASS**——median ratio **0.2054**（CI [0.1766, 0.2289]）；
  **机制 FAIL**——4 个问题选出的宽度全是 **[2,2,2,2]**（= 全局固定对照），
  且落在候选宽度零分布的 **0 分位**（p≤0.05）。
- 处置：主动关闭 adaptive claim，只保留"固定映射效率"窄结论。

### 4.7 第七层：深化（普查 / 机制理论 / 自审计）

- **CTRI 普查**（符号/秩稳定性）：5k → 100k → 10M 三档，
  reversal 率 **2.88% → 3.244% → 3.2744% ± 0.006pp**（收敛稳定）。

- **机制理论**（三条闭式推导，数值验证 ==0 偏差）：paired-replay 方差闭式、
  K-sample prefix floor、HH 的 1/q 放大。意义：知道"为什么是结构性的"。
- **自审计**：13 类故障注入自己的流水线，全部被预期 code 抓到，开发中

## 6. 三个"假货"完整故事（讲给面试官听）

**① 假成功曲线（起因）**
36.5% → 63.5% 的曲线；发现 rollout 用的是静态模型副本（trainer 更新了
权重，采样策略没换）；旧 logprob、token、mask 的身份也对不上。
处置：停手，不追幻影，改建审计系统。

**② 假方差（ρ=0.735）**
一个历史相关性 ρ=0.735 看起来很强。审计发现：计算它的场景里，备选动作
是 **no-op**（换了也不改变结果）——同一目标要么全成功要么全失败，
**奖励根本没有方差**。在没有方差的数据上算出的相关性是假的
（对应 E001/E003 与 A11 模板）。

**③ 假自适应（CPC 类 → 我的 D002）**
声称"自适应可变宽度"的方法指标确实赢（median ratio 0.205）。把校准选出的
参数摊开：宽度全是 2 = 全局固定对照。我主动关掉了自适应声明
（MECH001；统计上落在零分布 0 分位）。

**共同结构**：**一个看起来像证据的指标，其实没有在测量它声称的机制。**
四道门就是专门拆这类东西的。

## 7. 35 个高频拷问（直接回答 + 可展开 + 追问链）

### A 组：定位与意义

**Q1. 一句话说这个项目是干什么的？**
**A**：给 agent RL 的 credit assignment 方法做审计的工具：逼每个方法回答
四个问题——估什么、偏不偏、值不值、机制真不真。
**展开**：由两部分组成——精确可枚举基准世界（含双独立 oracle）+ 一套
reason-coded 门禁；接入后产出"哪道门过、哪道失败、为什么"的结构化裁决。
**追问**："四道门谁定的？" → 来自领域四类常见混淆（target 说不清、预算
不公、机制没发生、split 污染），在 design doc 里锁定，每道门都有 reason
code 和冻结回归 fixture。

**Q2. 不出新算法、没有 SOTA，价值在哪？**
**A**：这个生态最大的问题不是方法少，是"漂亮曲线"和"真实效果"经常脱节
（我自己就踩过）。我做的是把这种判断标准化、可复现化——**判别力就是产出**。
**展开**：量化的例子——V001 那类方法校准 1e-16 却固定预算差 26.5 倍；
没有审计，这个失败会被"校准很准"掩盖。
**追问**："工具自己准吗？" → 自审计：13 类故障注入全抓、零误报，
开发中抓出我自己 3 个 bug。

**Q3. 你自己方法被否决过吗？**
**A**：有——D002 的"自适应变宽"是我自己的路线，被自己的机制门否决
（宽度塌缩 [2,2,2,2]），我主动关掉 adaptive claim 只留窄结论。
**追问**："不心疼吗？" → 心疼；但保留它、将来被别人复现出塌缩更难堪。
审计工具的第一个用户必须是自己。

**Q4. 和 GRPO-Guard 什么关系？**
**A**：一条信任链两半。Guard 在线保证轨迹可信（身份、token/mask、日志
概率、权重同步）；Auditor 离线保证估计器可信。两个仓库互引：Guard 的
envelope 流进 Auditor 校验（hash-only、fail-closed、不写回）；Stage 3
就是"Guard 监督训练 + Auditor 审计轨迹"。
**追问**："schema 谁定？" → Guard 拥有它自己的 envelope schema；我不
fork、只读并按版本 pin。我的记录格式（aca-trajectory-record-1.0）是我
自己的，等 Guard 发布轨迹 schema 再做适配。

**Q5. 项目的边界？**
**A**：① 不声称真实 LLM 收益（Stage 3 最终指标未变，是机制级实验）；
② 精确世界不外推到真实分布；③ 历史数字只作事故背景。
**展开**：写进 claims 政策：允许说什么（有限 MDP 无偏性、matched-budget
比较、机制失败演示）、禁止说什么（"新算法""真实收益""K=8 证明自适应"）。

### B 组：方法论深挖

**Q6. 精确小世界不是玩具吗？**
**A**：三层。① 小世界的价值在**可控**（真实场景没有真值，测不了偏差）；
② **证据桥**：exact 预测公式复现采样 MSE，比率 0.87-1.07；③ **真实闭环**
18 次训练。我声称的是"判断方法能迁移"，不是"小世界代表真实分布"。
**追问**："0.87-1.07 怎么算的？" → 每个"估计器×任务"：精确层算预测
MSE（var·cost/B + bias²），采样层同预算跑 40 个重复批次测 MSE，比值
= 实测/预测，全部落在区间内。

**Q7. oracle 会不会和主实现共谋 bug？**
**A**：不同算法（枚举 vs DP）+ 独立子进程 + stdlib-only + AST import
隔离 + monkeypatch 破坏测试；再加分数精确算术对齐（12 问题 mismatch==0）。
不一致就判 INVALID，不"选一个信一个"。
**追问**："两个 oracle 都错呢？" → 独立实现错成同样数值概率极低；而且
关键结论（57× 正例、T003 拒绝）都有闭式推导 cross-check（机制理论
三条公式，数值验证 ==0）。

**Q8. 机制门标准是不是你定的？会不会过严？**
**A**：预注册（跑前写进协议并哈希冻结）。判据：自适应映射校准出的参数
若与固定对照完全一致（无多样性）→ MECH001。还升级成统计检验：D002 的
[2,2,2,2] 落在零分布 0 分位（p≤0.05）。
**追问**："误判怎么办？" → 把结论窄化（关掉 adaptive 只留固定映射），
而不是硬留。

**Q9. V001 的 26.5 倍怎么来的？**
**A**：① 1/q 方差放大：`Var = Var(R·s)/q + g*²(1/q−1)`；② 分支成本：
每次校正多跑一段对比轨迹。期望是对的（校准 1.5e-16），固定预算 MSE 中位数
26.53 倍（CI [16.78, 42.87]）；vs HH 也是 3.06 倍（CI [2.68, 3.30]）。
**追问**："预算太紧？" → 预算是预注册的，且两个基线方向一致。

**Q10. 57× 正例是不是调出来的？**
**A**：预注册 designed world（决策日志 D8/D9）。两个让它有意义的证据：
① uncoupled 对照组输 dense 7 倍 → 赢的是配对机制；② 讲的时候主动区分
designed vs discovered。
**追问**："为什么配对能赢？" → 同前缀两分支共享后缀噪声，对比量方差
被消掉一大块（有闭式方差公式）；dense 无偏但周期方差大，固定预算吃亏。

**Q11. 执行中最大的难题？怎么解决的？**（必练）
**A**：Stage 3 真实闭环，三个难题：
① **vLLM 在两台服务器都起不来**——一台 Blackwell 新架构（SM 12.x 需要
更新的 CUDA），一台环境冲突。改成**训练器自身采样 + Guard 的
`exact_behavior_scorer` 模式**（训练器生成并精确打分自己的样本），并把
"未启用 vLLM 生成服务"写进每个 run 的 metrics 作为限制。
② **显存 OOM**——256 条序列一次前向 float logits ~31GB。改成**分块反向
传播**：每 8 条算一次 loss 立即 backward、梯度累加，40GB 卡也能跑。
③ **共享服务器资源争抢**——别人随时抢卡、我的训练被 kill。写**GPU 门控
自愈启动器**：只捡 ≤1GB 空闲卡（优先卡序）、有他人进程就等待重试、
断点续跑（metrics.json 存在即跳过）。
**追问**："怎么区分你的 bug 和环境问题？" → smoke 先跑通（8 prompt 单
epoch）再推满配；OOM 是 CUDA 明确报错；被 kill 是 rc=137（SIGKILL）
而非异常退出。

**Q12. 共享服务器怎么不干扰别人？**
**A**：只用空闲卡（≤1GB 占用）、一次一张、检测到他人进程就等待、
重活优先 CPU。实际 18 次训练期间别人在占 3 张卡跑评测，两边互不干扰。
**追问**："全被占了呢？" → 启动器进等待循环（5 分钟一查），不抢占。

**Q13. paired 门 9/9 弃权——bug 还是发现？**
**A**：发现。三层排除：① 单测覆盖门的三态逻辑；② 同环境对照——dense/local
正常更新（4.89/4.86），不是框架问题；③ 原因可解释——58% 样本无效调用、
效用矩阵太平，统计上不可靠 → 门弃权。
**展开**：预注册预测 4 说"门会关"；但"后期恢复"没发生——如实报告
预测部分被证伪。
**追问**："方法没用？" → 不能这么推；给出的是**边界条件**：基础模型能力
不足、数据一半无效时，保守门全程关闭。

**Q14. tau2 全零奖励，为什么不换任务？**
**A**：① 换到满意 = 挑结果，违反预注册（正是 D002_TEST_TIME_RESElection
要防的）；② 负结果有信息：量化"基础模型 + 稀疏奖励"的冷启动问题。
**追问**："学到什么？" → 这类任务要先做格式预热（先学会输出合法调用），
写进了报告分析。

**Q15. 怎么保证可复现、没有选择性报告？**
**A**：协议冻结（协议+种子跑前哈希）、no-overwrite（重跑必须新目录）、
证据链（数字 → artifact + commit + SHA256SUMS）、fresh-clone 一键复现
（CI 里跑）。全量上报：V001 效用失败、D002 机制失败、门弃权、零奖励，
全部在报告里。
**追问**："决策日志？" → 每次偏离设计的决定都要记录：决定、证据、替代
方案、为什么拒绝、可证伪条件（如 D10 删 v0.1.5 包、D13 换采样方式）。

**Q16. 为什么用 Fraction 而不用普通浮点？**
**A**：浮点有舍入误差，"1e-16"到底是真偏差还是噪声说不清。分数精确算术
让"mismatch == 0"是**精确的零**。开销量级在这个问题上完全可接受
（10M 家族普查 88 秒跑完）。

**Q17. K-sample prefix floor 是什么？**
**A**：共享前缀估计器有方差下限：`Var = E[Var|prefix] + Var(E[·|prefix])`，
第二项只由前缀决定，**后缀采多少都消不掉**。这就是"加宽采样"类方法的
固定预算天花板；也是我解释"为什么某个历史数字在正确协议下不复现"的
理论依据。

**Q18. 项目里你犯过的错 / 最大教训？**（必练，准备三层次）
**A**：① **发布事故**：v0.1.5 发布后 Linux 上 73/98 校验和对不上，根因是
换行符（CRLF vs LF）——修复：统一 LF + 写入端显式 LF + CI 加"发布物必须
通过自己审计"的门。教训：**证据类问题必须用目标平台在 CI 上验证**。
② **自己方法的假结果**：D002 的 adaptive claim 被自己的机制门否决。
教训：**标准要在看结果之前定**。
③ **执行教训**：ssh 超时调用在服务器上留下"幽灵启动器"互相干扰。
教训：**远程执行要幂等的启动 + 可观测状态**，不能靠"再试一次"。

**Q19. 10 倍算力你会做什么？**
**A**：① Stage 3 扩规模（更多 epoch / 更大 rank）让最终指标动起来，检验
"机制级判断能否预测效果级排序"；② tau2 类任务加格式预热阶段并量化影响；
③ 真实轨迹上做全部六类故障注入（现在在冻结 fixture 上）。

**Q20. 最难的技术点？**
**A**：**机制的独立验证**。测偏差有标准做法（对 oracle），但"正结果真来自
声称机制吗"没有现成标准——要先想清楚"机制为假会留下什么指纹"，再设计
检查。我的答案：让方法自己校准参数、把参数摊开对比固定对照。

**Q21. 工业界有什么用？**
**A**：① 训练管线回归防线：新 credit/advantage 方法上线前做 target/成本/
机制三项体检；② 轨迹审计直接可用：检查 optimizer 实际消费的数据（mask
对齐、policy 版本、日志概率绑定）——这类 bug 在生产里常见且隐蔽。

**Q22. 和其他人怎么协作？**
**A**：边界清晰 + 接口稳定 + 失败可检测。Guard 拥有自己的 schema，我
hash 引用 + fail-closed；两个项目独立演进但共享同一套故障分类。

### C 组：陷阱与压力题

**Q23. 能推广到真实 LLM 训练吗？**
**A**：能推广的是**方法**（审计流程、预测公式、故障分类）；不能推广的是
**数字**。Stage 2/3 就是为这个问题设计的：预测公式在可控世界成立
（0.87-1.07），真实闭环跑通但最终指标未变。

**Q24. 那到底证明了什么？**
**A**：① 审计流程可行且自动（四门 + 23 code + 13 模板回归）；② 一批
具体方法性质被量化（无偏/有偏/机制退化）；③ exact→sampled 的预测关系
成立（0.87-1.07）。

**Q25. 1e-16 是不是浮点噪声？**
**A**：核心计算用 Fraction（有理数），"mismatch == 0"是精确零；1e-16 出现
在需要转浮点展示的地方（如偏差打印）。不需要符号计算——分数已是精确
有理数运算。

**Q26. 为什么 10⁷ 这个规模？不是伪收敛吗？**
**A**：三档跨两个数量级；2.88% → 3.244% → 3.2744% 单调收敛且幅度递减，
10M 的 ±0.006pp 与 100k 重叠。每档都是**全量精确统计**（非抽样），
生成与判据在协议里冻结。

**Q27. 给你一个真实训练日志，能审吗？**
**A**：能审**结构性故障**：mask 与 token 长度、日志概率长度、策略版本
缺失/混用、估计器掩码 ≠ 优化器消费掩码、不可解析记录。不能直接审
"有没有偏"——那需要真值或受控环境。流程：先轨迹审计清数据层问题，
再在受控环境审方法层。

**Q28. 和 advantage 归一化冲突吗？**
**A**：不冲突——审计的是"目标对不对、预算公不公平、机制真不真"。
若归一化改变了 estimand（比如标准化让目标依赖同批次其他样本），
那正是 T001/T002 要问的：你估的量到底是什么。

**Q29. 对你成长最大的是什么？**
**A**：学会**在被结果诱惑时不改标准**。预注册、决策日志、claims 政策
写起来麻烦，但正是 D002 那种"我的方法指标赢、机制输"的时刻，让我能做
正确处置而不是自我欺骗。

**Q30. 有什么问题问我们？**（反问，准备 3-5 个）
- 团队训练管线的"回归防线"怎么做的？有没有对 credit/advantage 变更的
  自动体检？
- 你们更看重"新方法带来收益"还是"把已有方法的可靠性说清楚"？
- 如果要把轨迹审计接到你们的训练栈，第一步该对接什么数据？

### D 组：简历与背景追问

**Q31. 这个项目你独立完成吗？用了什么现成工具？**
**A**：独立完成设计与实现。使用了社区工具作为基础设施（transformers /
PEFT / TRL / pytest 等），但审计逻辑、精确世界、oracle、门禁、真实闭环
脚本都是自己写的；GRPO-Guard 是我自己的另一个项目，两边通过接口对接。
**追问**："有没有参考工作？" → 审计思路参考经典统计检验（有偏/无偏、
置信区间、bootstrap）、抽样理论（HH/HT 估计量）和 RL 的 credit
assignment 文献；工具本身没有直接对标物。

**Q32. 18 次训练怎么排除是 seed 偶然？**
**A**：每个"方法×任务"跑 3 个种子并报均值（REPORT.md 里逐种子列出）；
更关键的是**结论方向在 3 个种子上一致**（比如 paired 门 9/9 全弃权、
dense/local 梯度范数尺度稳定）。另外任务是两个不同结构（cts_order 与
tau2），避免单一任务的偶然性。

**Q33. 为什么用 LoRA 不全参训练？**
**A**：实验目标是**机制级比较**（估计器的梯度行为、门的行为），不是
刷效果——LoRA 让 18 次训练在共享卡上可执行（显存和时间都可控），
同时保留了"更新真实发生"的证据（每次提交的 adapter 有 sha256、
canary 检查权重差异非零）。

**Q34. 这个项目里你最自豪的一个设计？**
**A**：**双独立 oracle 的四条隔离保证**（不同算法 + 独立进程 + stdlib-only
+ AST/monkeypatch 测试）。因为它让"1e-16、0 偏差"这种说法不是自我声明，
而是可验证事实——这是整个项目可信度的地基。

**Q35. 下一步计划？**
**A**：三件事按优先级：① Stage 3 扩规模让最终指标动起来（验证"机制判断
预测效果排序"）；② tau2 类任务加格式预热，量化冷启动；③ Guard 发布轨迹
schema 后，把轨迹审计接到真实 Guard 记录上做 estimator 级审计。
